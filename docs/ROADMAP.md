# 希音 · 阶段路线图（草案）

| 阶段 | 目标 | 关键交付 | 验收 |
|---|---|---|---|
| **A · 立项与边界** | 定死四类内容的范围与合规边界 | 音源清单、目标车机矩阵、驾驶安全交互规范、隐私策略 | 四份文档评审通过；原型演示得到认可 |
| **B · 底座复用** | 从 MyGo Car 抽出可复用壳 | `apps/car` 能独立编译；`packages/plugin-sdk` 接口冻结；依赖/合并策略落地 | 现有三插件在新壳中全部可用；14 项仪器化测试迁移通过 |
| **C · 新能力** | 播客/有声书/语音/离线 | 至少 2 个新音源插件、语音意图层、Media3 离线缓存 | 通勤场景端到端：离线听完整一章且进度正确 |
| **D · 真机验证** | 车机实车验证与发布 | 真机报告、性能数据、崩溃率、Release 包 | 连续 2 小时播放无 FATAL；驾驶场景下盲操可用 |

## 阶段 A 的四份必交文档

1. **音源清单**：每类内容至少 2 个候选源，标注 API 条款、版权与登录要求；
2. **车机矩阵**：分辨率、Android 版本、输入方式（触摸/旋钮/方向盘按键）；
3. **驾驶安全规范**：行驶中允许/禁止的操作，语音优先级，最大嵌套层级；
4. **隐私策略**：凭据与收听历史的存储位置、加密方式、清理入口。

## 依赖与风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 音源 API 条款变化 | C 阶段插件不可用 | A 阶段就做条款快照，优先选官方开放接口 |
| 车机屏幕碎片化 | UI 适配成本高 | 先限定 2 个分辨率，抽象 `WindowMetrics` 层 |
| 驾驶安全合规 | 功能被砍 | A 阶段定死交互边界，不事后补 |
| 底座与希音双线维护 | 重复修复 | B 阶段确定 monorepo 或依赖发布，避免复制源码 |
